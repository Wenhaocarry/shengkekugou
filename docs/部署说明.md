# 部署说明

## GitHub 版本范围

仓库根目录是 V3 项目源码，对应本地 `shengke-v3/`，发布分支为 `master`。V1、V2、本地 `data/`、上传照片与音频、可执行文件、构建缓存和运行截图不随源码上传。

克隆后可使用 Go 1.22+ 本地启动：

```sh
git clone https://github.com/Wenhaocarry/shengkekugou.git
cd shengkekugou
./start.sh -expand-playlist-demo
```

默认访问 `http://127.0.0.1:8099/`。第一次运行会生成演示音频及示例记录；`-expand-playlist-demo` 追加至 12 首示例歌单，可以重复执行，不覆盖已有记录。

## Vercel 兼容性

Vercel 支持 Go Functions，但运行入口是 `api/` 目录中的 HTTP handler；当前项目运行的是 `main.go` 常驻 HTTP 服务，不能只导入仓库就得到完整可用的后端。

当前记录写入 `data/state.json`，媒体写入 `data/media/`，并使用文件锁和内存互斥管理单进程写入。Vercel Functions 文件系统只读，只有临时目录可写；临时目录不能作为记录与上传图片的长期存储，多实例之间也不能共享本地内存和锁。

因此，本仓库保留当前完整 Go 版本，不添加会让记录在冷启动后丢失的临时存储部署配置。

完整部署至 Vercel 需要：

1. 将 HTTP 服务适配为 Go Function 入口，并配置前端、API 和媒体路由。
2. 将记录迁移到支持并发更新的云数据库，图片与音频改用对象存储。
3. 在 Vercel 项目中配置存储连接信息；凭据使用环境变量，不提交 GitHub。
4. 配置访问限制。当前 Demo 是单用户共享数据模型；公开站点若允许多人使用，需要补充登录和用户数据隔离。

如果只需要在线演示，也可以另做浏览器本地持久化版本。它能避免额外后端存储，但记录会按浏览器分别保存，不能视为当前 Go 后端的跨设备持久化部署。
