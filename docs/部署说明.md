# 部署说明

仓库根目录对应 V4，发布分支为 `master`。本地 Go 版和浏览器演示版共用 UI 与交互。

## Vercel 浏览器演示版

用户选择的线上方式为浏览器演示版。Vercel 只提供静态文件，记录、照片和上传歌曲保存在各自浏览器的 IndexedDB 中；不会上传到网站服务器，也不跨设备同步。清除本站数据或使用无痕窗口，会影响本地记录；重要内容可导出 JSON 或完整 ZIP 备份。

首次打开使用 12 首原创合成音频和 17 条明确标识的示例记录。本地 `data/`、真实上传图片、音频、缓存和运行截图不会进入 GitHub 或构建产物。

### 本地构建和预览

需要 Node.js；构建不安装第三方依赖：

```sh
npm run build
npm run preview
```

打开 `http://127.0.0.1:8090/`。`scripts/build-demo.cjs` 复制页面和素材、生成合成音频，并将入口切换至浏览器存储适配。构建只读取 `web/` 和经过校验的 `samples/browser-demo-state.json`。

### 导入 Vercel

1. 在 Vercel 中导入 `Wenhaocarry/shengkekugou`。
2. Root Directory 使用仓库根目录，生产分支选择 `master`。
3. Framework Preset 选择 Other；`vercel.json` 已配置 Build Command 为 `npm run build`、Output Directory 为 `dist`。
4. 无需数据库、对象存储或环境变量。
5. 部署完成后检查首页、播放队列、记忆创建、照片、刷新保留记录、分享和 ZIP 备份。

`vercel.json` 同时配置安全响应头；浏览器测试按这些响应头执行。

### 浏览器回归测试

安装或使用本机已有的 Chrome 和 Playwright 后：

```sh
npm run build
node ui-smoke.test.cjs --browser
```

Playwright 可通过 `NODE_PATH` 指向本机已有包。测试创建隔离的浏览器上下文，不读取用户真实浏览器数据。覆盖原有 UI 流程、刷新与跨标签页持久化、跨浏览器隔离、三张照片、音频上传、完整备份 ZIP 校验。

## 本地 Go 版

```sh
./start.sh -expand-playlist-demo
```

默认访问 `http://127.0.0.1:8100/`；记录仍保存到 `data/`。本地入口直接加载 `kugou.js`，不启用浏览器存储适配。`-expand-playlist-demo` 追加至 12 首示例歌单，可重复执行，不覆盖已有记录。

Go 的常驻服务和本地文件存储没有直接运行在 Vercel。未来如果要做跨设备共享的完整线上版，需要云数据库、媒体存储，以及登录和用户数据隔离。
